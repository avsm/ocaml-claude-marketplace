# OxCaml Base Library Extensions

For `base v0.18~preview.133.03+642` (OxCaml 5.4.0-ox9). When a call
fails to typecheck, read the `.mli` under `$(opam var lib)/base/`.

## How Base Names Its Mode Variants

Almost every variant below is generated by `ppx_template` — most Base
modules use `%%template` (and `%%rederive`); see
[SKILL-TEMPLATES.md](SKILL-TEMPLATES.md).

| Suffix | Meaning | Select with |
|--------|---------|-------------|
| `f__local` | accepts **local input** (and local closures args) | `(f [@mode local])` |
| `f__stack` | **result is stack-allocated** (`@ local`) | `(f [@alloc stack])` |
| `f__local__stack` | both | `(f [@mode local] [@alloc stack])` |
| `f__local__global`, `f__global__local`, `f__local__local` | two mode variables (e.g. `fold`: input mode, accumulator mode) | `(f [@mode local global])` |
| `f__portable` | portable instance (functors, constructors) | `(f [@mode portable])` |
| `f__shared` | works on `shared` (read-only, cross-thread) values | `(f [@mode shared])` |
| `f__sync` | synchronised instance for `shared` values | `[%template (f [@synchro sync])]` (needs the `%template` node) |

**Prefer the attribute form** — it is stable, whereas mangled names
are not guaranteed. `__local` does **not** mean "returns a local
result"; that is `__stack`.

```ocaml
val List.map            : 'a t -> f:('a -> 'b) @ local -> 'b t
val List.map__local     : 'a t @ local -> f:('a @ local -> 'b) @ local -> 'b t
val List.map__stack     : 'a t -> f:('a -> 'b @ local) @ local -> 'b t @ local
val List.map__local__stack
  : 'a t @ local -> f:('a @ local -> 'b @ local) @ local -> 'b t @ local
```

Most Base collection functions follow these patterns:

| Standard | Variants | Purpose |
|----------|----------|---------|
| `map` | `map__local`, `map__stack`, `map__local__stack` | local input / stack result / both |
| `filter` | `filter__stack` | local input, stack result |
| `filter_map`, `concat_map` | `__local`, `__stack`, `__local__stack` | as `map` |
| `fold` | `fold__local__global`, `fold__global__local`, `fold__local__local` | input mode, accumulator mode |
| `iter` | `iter__local` | local input |
| `exists`, `for_all` | `exists__local`, `for_all__local` | local input |
| `find` | `find__local` | local input, local option result |
| `find_map` | `find_map__local__global`, `find_map__global__local`, `find_map__local__local` | input mode, result mode |
| `init`, `append`, `rev`, `of_list` | `init__stack`, … | stack result |

There is no `filter__local` or plain `fold__local` — `filter` only has
a `__stack` instance, and `fold` needs both modes named.

## Module Overview

| Module | OxCaml features |
|--------|-----------------|
| `Array` | `@local_opt`, `@layout_poly` get/set/length, `init__stack`, `create__stack`, `get__shared` |
| `Iarray` | `Local` and `Unique` submodules, `__local`/`__stack` variants |
| `List` | full `__local` / `__stack` / `__local__stack` family |
| `Nonempty_list` | same family as `List` |
| `Option_array` | `get_local`; `length` accepts `@ local` |
| `Hashtbl` | `iter__local`, `iteri__local`, `iter_keys__local`; shared-mode readers `find__shared`, `mem__shared`, `length__shared`, `iter__sync`, `fold__sync`; `create__portable`, `of_alist__portable` |
| `Hash_set` | `equal__local` only |
| `Hashable` | `of_key__portable` (the `Make` functors live in **Core**) |
| `Set`, `Map` | `equal__local` (`Set` also `compare__local`), `compare_m__t__local`, `empty__portable`, `sexp_of_m__t__stack` (no local folds) |
| `Avltree` | kind-templated; `__shared` readers (`find__shared`, `mem__shared`, …) |
| `Dictionary_immutable`, `Dictionary_mutable` | mode-aware signatures |
| `Queue` | `compare__local`, `equal__local`, `sexp_of_t__stack` |
| `Stack`, `Linked_queue` | no mode variants |
| `Container`, `Indexed_container` | mode-templated signatures |
| `Comparable` | `min__local`/`max__local`, `lexicographic__local` |
| `Comparator` | mode-aware |
| `Comparisons` | `@local_opt` |
| `Type_equal` | mode-safe |
| `Bool`, `Char`, `Unit` | `compare__local`, `equal__local`, `min__local`/`max__local` |
| `Int`, `Int32`, `Int64`, `Nativeint` | `@local_opt` conversions, `min__local`/`max__local` |
| `Float` | math ops with local support |
| `String` | `split__stack`, `concat__stack`, `sub__stack`, `map__stack`, `fold__local__global`, … |
| `Bytes` | `create__stack`, `make__stack`, `sub__stack`, `to_string__stack` |

Most extensive support (use these first): `Iarray` (the most
OxCaml-friendly array module), `List`, `Array`; then `Option`,
`Result`, `Or_error`, `Or_null`.

## The `Modes` Module

Zero-cost wrappers for crossing between mode contexts, on five axes:
locality (`local`, `global`), portability (`nonportable`, `portable`),
contention (`uncontended`, `shared`, `contended`), linearity (`once`,
`many`), uniqueness (`unique`, `aliased`). The compiler has more axes —
see [SKILL-MODES.md](SKILL-MODES.md).

Each wrapper is an `[@@unboxed]` record with one field carrying a
modality:

```ocaml
module Global : sig
  type ('a : value_or_null) t = { global : 'a @@ global } [@@unboxed]
  val wrap : 'a -> 'a t
  val unwrap : 'a t @ local -> 'a
end

module Portable : sig
  type ('a : value_or_null) t = { portable : 'a @@ portable } [@@unboxed]
  external wrap : ('a[@local_opt]) @ portable -> ('a t[@local_opt]) @ portable
    = "%identity"
  external unwrap : ('a t[@local_opt]) -> ('a[@local_opt]) @ portable
    = "%identity"
end

(* Contended : { contended : 'a @@ contended }
   Shared    : { shared    : 'a @@ shared }
   Portended : { portended : 'a @@ portable contended }
   Many      : { many      : 'a @@ many }
   Aliased   : { aliased   : 'a @@ aliased } *)
```

Other submodules: `Aliased_many`, `Forkable`, `Unyielding`,
`Stateless`, `Reading`, `Immutable`, `Read`, `Immutable_data`,
`At_locality`, `At_portability`, `Portable_via_contended`,
`Contended_via_portable`, `Many_via_aliased`, `Aliased_via_many`,
`Mod`, `Export`.

The record fields can be used directly:

```ocaml
open Base

let w : int ref Modes.Global.t = Modes.Global.wrap (ref 1)
let w2 = { Modes.Global.global = ref 1 }
let { Modes.Global.global = g } = w2
let p = { Modes.Portable.portable = fun x -> x + 1 }
let pc : int Modes.Portended.t = { portended = 1 }
```

The wrappers don't launder modes — `Global.wrap` needs a value that is
already global. Their point is *storage*: a `'a Modes.Global.t` keeps
its contents global even inside a local (or unique) data structure:

```ocaml
(* Keep a global value global inside a local container *)
let local_ pair = (Modes.Global.wrap config, scratch_buffer)

(* Contents can escape even though the container is local *)
let extract ((g, _) @ local) =
  Modes.Global.unwrap g   (* global result - fine to return *)
```

## Collections

### `Iarray`

```ocaml
module Iarray : sig
  type 'a t  (* = 'a iarray; immutable, covariant *)

  (* Standard access *)
  val get : 'a t -> int -> 'a
  val length : 'a t -> int

  (* Local submodule - stack-allocated results *)
  module Local : sig
    val init : int -> f:(int -> 'a @ local) @ local -> 'a t @ local
    (* Uses O(n) function-call stack space *)

    val init_with_globals : int -> f:(int -> 'a) @ local -> 'a t @ local
    (* Elements must be global - avoids extra stack space *)
  end

  (* Unique submodule - for unique-mode construction *)
  module Unique : sig
    val init : int -> f:(int -> 'a @ unique) -> 'a t @ unique
    val map : 'a t @ unique -> f:('a @ unique -> 'b @ unique) @ local -> 'b t @ unique
    (* also mapi, iter, iteri, of_array, unzip, zip_exn *)
  end
end
```

Plus the same `__local` / `__stack` family as `List`
(`map__stack`, `filter__stack`, `fold__local__global`, `zip__stack`,
`iter__local`, …).

```ocaml
open Base

(* Returns a stack-allocated iarray: needs exclave_ *)
let make_lookup_table size = exclave_
  Iarray.Local.init size ~f:(fun i -> compute_entry i)

let use size =
  let local_ tbl = Iarray.Local.init_with_globals size ~f:compute_entry in
  Iarray.length tbl
```

### `List`

Signatures beyond the `map` family above:

```ocaml
val filter__stack : 'a t @ local -> f:('a @ local -> bool) @ local -> 'a t @ local

(* two mode variables: input mode, then accumulator mode *)
val fold__local__global
  : 'a t @ local -> init:'b -> f:('b -> 'a @ local -> 'b) @ local -> 'b

(* local input, no allocation *)
val iter__local : 'a t @ local -> f:('a @ local -> unit) @ local -> unit
val exists__local : 'a t @ local -> f:('a @ local -> bool) @ local -> bool
val find__local : 'a t @ local -> f:('a @ local -> bool) @ local -> 'a option @ local
```

A pipeline (`[@nontail]`: a call that takes a local argument can't be
a tail call):

```ocaml
open Base

let process_items items =
  let local_ filtered = (List.filter [@alloc stack]) items ~f:is_valid in
  let local_ mapped =
    (List.map [@mode local] [@alloc stack]) filtered ~f:transform
  in
  (List.fold [@mode local global]) mapped ~init:0 ~f:( + ) [@nontail]
  (* Final result is a global int *)
```

```ocaml
open Base

(* find__local returns a local option *)
let find_first_valid_local (items @ local) = exclave_
  (List.find [@mode local]) items ~f:(fun x -> is_valid x)

(* Your own template can forward the choice *)
let%template[@alloc a @ m = (heap_global, stack_local)] my_map lst ~f =
  (List.map [@alloc a]) lst ~f [@exclave_if_stack a]
(* my_map, my_map__stack *)
```

### `Array`

```ocaml
(* Layout-polymorphic operations: work on float# array, int64_u array, … *)
external length
  : ('a : any mod separable). ('a array[@local_opt]) @ immutable -> int
  = "%array_length" [@@layout_poly]

external get
  : ('a : any mod separable). ('a array[@local_opt]) -> (int[@local_opt]) -> 'a
  = "%array_safe_get" [@@layout_poly]
(* get also has a shared-mode instance: (Array.get [@mode shared]) *)

(* Heap or stack result *)
val init : int -> f:(int -> 'a) @ local -> 'a array
val init__stack : int -> f:(int -> 'a) @ local -> 'a array @ local
```

Because these are layout-polymorphic, `open Base` makes `a.(i)`,
`a.(i) <- v` and `Array.length a` work on unboxed-element arrays —
the plain `Stdlib.Array` functions reject them.

### `Hashtbl`

A `Hashtbl.t` cannot be stack-allocated (its buckets are heap data),
so don't mark it `local_`; just let it become garbage.
`Hashtbl.choose__local` is now spelled `Hashtbl.choose_local`.

## `Option`, `Result`, `Or_error`, `Or_null`

**`Option`**

```ocaml
val map__local
  : 'a t @ local -> f:('a @ local -> 'b @ local) @ local once -> 'b t @ local
val bind__local
  : 'a t @ local -> f:('a @ local -> 'b t @ local) @ local once -> 'b t @ local
val value__local : 'a t @ local -> default:'a @ local -> 'a @ local
(* also merge__stack, try_with__stack, iter__local, some__local, … *)
```

**`Result`**

```ocaml
val map__local
  : ('a, 'err) t @ local -> f:('a @ local -> 'b @ local) @ local once
  -> ('b, 'err) t @ local
val bind__local
  : ('a, 'err) t @ local -> f:('a @ local -> ('b, 'err) t @ local) @ local once
  -> ('b, 'err) t @ local
val map_error__stack
  : ('ok, 'err) t @ local -> f:('err @ local -> 'c @ local) @ local once
  -> ('ok, 'c) t @ local
```

**`Or_error`**

```ocaml
val map__local : 'a t @ local -> f:('a @ local -> 'b @ local) @ local -> 'b t @ local
val bind__local : 'a t @ local -> f:('a @ local -> 'b t @ local) @ local -> 'b t @ local
val try_with__stack : ?backtrace:bool -> (unit -> 'a @ local) @ local once -> 'a t @ local
```

`Or_error.Portable` is `('a, Error.Portable.t) Result.t` — an error
type that is safe to send across domains — with `error_s`,
`error_string`, `errorf`, `tag`, `try_with`, `of_exn`. Convert with
`Or_error.of_portable`, `Or_error.to_portable` and
`Or_error.portabilize`.

**`Or_null`** — non-allocating option alternative (re-exports the
built-in `or_null`):

```ocaml
type 'a t = 'a or_null = Null | This of 'a [@@or_null_reexport]

val to_option__local : 'a t @ local -> 'a option @ local  (* [@@zero_alloc] *)
val value__local : 'a t @ local -> default:'a @ local -> 'a @ local
```

Many Base functions have `_or_null` twins that avoid the `Some`
allocation: `List.find_or_null__local`, `List.filter_map_or_null__stack`,
`Array.get_or_null`, `Hashtbl.find_or_null__shared`,
`Hashtbl.find_and_remove_or_null`, `Map.update_or_null`.

## Portable Functors

The functors that build comparison/hash infrastructure have portable
instances. `Comparable.Make` and `Hashable.Make` are **Core** functors
(`Base.Hashable` has no `Make`):

```ocaml
open Core

module Cache_key = struct
  module T = struct
    type t = { domain : string; path : string }
    [@@deriving compare, sexp, hash]
  end
  include T
  include Comparable.Make [@mode portable] (T)
  include Hashable.Make [@mode portable] (T)
end

(* Equivalent, with include functor *)
module Cache_key2 = struct
  type t = { domain : string; path : string }
  [@@deriving compare, sexp, hash]
  include functor Comparable.Make [@mode portable]
  include functor Hashable.Make [@mode portable]
end
```

(`Comparable.Make__portable (T)` is the same instance by its mangled
name.) To write your *own* functor in both flavours, use
`module%template.portable` and forward the modality — see
"Shorthand: %template.portable" in
[SKILL-TEMPLATES.md](SKILL-TEMPLATES.md).

## Lazy Evaluation

```ocaml
external force : ('a t[@local_opt]) -> 'a = "%lazy_force"
(* Can force local lazy values *)
```

`Portable_lazy` — thread-safe lazy evaluation for portable values:

```ocaml
module Portable_lazy : sig
  type 'a t

  val from_val : 'a @ portable contended -> 'a t
  val from_fun : (unit -> 'a @ portable contended) @ once portable -> 'a t
  (* Function must be portable - can run on any domain *)

  val force : 'a t @ local -> 'a @ portable contended
  (* also map, bind, Let_syntax *)
end
```

## Utility Modules

**`With_return`**

```ocaml
val with_return : ('a return -> 'a) @ local -> 'a
val with_return_option : ('a return -> unit) @ local -> 'a option
(* The body closure may be local (stack-allocated); results are global *)
```

**`Staged`**

```ocaml
external stage : ('a[@local_opt]) -> ('a t[@local_opt]) = "%identity"
external unstage : ('a t[@local_opt]) -> ('a[@local_opt]) = "%identity"
(* Zero-cost staging with local support; also stage__portable *)
```

**`Fn`**

```ocaml
external ( |> ) : ('a : any) ('b : any). 'a -> (('a -> 'b)[@local_opt]) -> 'b
  = "%revapply" [@@layout_poly]
(* Layout-polymorphic pipe with local function support *)
```

## Unboxed Numeric Modules

The unboxed-number modules are **not in Base** — they come from the
`unboxed` package (`(libraries core unboxed)`), which provides
top-level `Float_u`, `Int32_u`, `Int64_u`, `Nativeint_u`, `Float32_u`:

```ocaml
module Float_u : sig
  type t = float#
  val add : t -> t -> t
  val sub : t -> t -> t
  val neg : t -> t
  val abs : t -> t
  val sqrt : t -> t
  val ( + ) : t -> t -> t      (* also - * / ** and comparisons *)
  val of_float : float -> t
  val to_float : t -> float
  (* box / unbox, of_int, round_*, iround_*, … *)
end

module Int32_u : sig
  type t = int32_u
  val ( + ) : t -> t -> t      (* also - * / % land lor lsl … *)
  val neg : t -> t
  val abs : t -> t
  val of_int32 : int32 -> t
  val to_int : t -> int option (* also to_int_exn, to_int_trunc *)
  (* box / unbox, of_int_exn, of_int_trunc, … *)
end

module Int64_u : sig
  type t = int64_u
  (* same pattern, plus of_int : int -> t *)
end
```

Gotchas:

- The unboxed number types are spelled `int32_u`, `int64_u`,
  `nativeint_u`, `float32_u` (the `int32#`… spellings were removed
  from the compiler; `float#` is unchanged). `Int32_u.t = int32_u` etc.
- Arithmetic on the integer modules is by **operators** (`Int64_u.(a + b)`);
  only `Float_u` (`add`, `sub`) and `Float32_u` (`add`, `sub`, `mul`,
  `div`) have named functions. There is no `Float_u.mul`.
- `to_int` returns `int option`; use `to_int_exn` or `to_int_trunc`.
- `open Unboxed` gives short aliases `F64`, `F32`, `I32`, `I64`,
  `Iptr` (and types `f64`, `i64`, …).
- The `Int64_u.Array` / `Int32_u.Array` / `Nativeint_u.Array` helper
  modules (and `Array_index`, `Iarray_index`) are gone from `unboxed`:
  `Array.get` / `set` / `length` already work on unboxed-element
  arrays, other functions take a kind instance
  (`(Array.map [@kind bits64 bits64])`), and indexing by an unboxed
  integer is in the `unboxed_indexing` library
  (`Unboxed_indexing.Array.Indexed_by_int64.get`).
- **Deriving on a bare `int64_u` field fails** under `open Base`/
  `open Core` (`Error: Unbound value sexp_of_int64_u`; likewise
  `int32_u`, `nativeint_u`, `float32_u` — `Base.Export` no longer
  provides these converters). Spell the field through the module:

```ocaml
open Core

type t =
  { x : Int64_u.t
  ; y : float#            (* float# is fine as-is *)
  ; z : Int32_u.t
  ; w : Float32_u.t
  }
[@@deriving sexp_of]
```

## Deriving with Modes

The Jane Street derivers take flags that generate the local/stack
instances:

```ocaml
open Core

type t = { a : int; b : string }
[@@deriving
  compare ~localize      (* compare__local : t @ local -> t @ local -> int *)
  , equal ~localize      (* equal__local *)
  , sexp_of ~stackify    (* sexp_of_t__stack : t @ local -> Sexp.t @ local *)
  , globalize]           (* globalize : t @ local -> t *)
```
